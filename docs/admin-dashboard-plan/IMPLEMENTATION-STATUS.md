# Implementation status

This document records implementation evidence for the admin-dashboard plan. It is intentionally not a production-completion claim.

## Completed in the current working tree

- Light-first admin shell with persisted Light / Dark / System preference.
- Responsive admin navigation with every currently implemented admin area exposed as a single canonical navigation model.
- Honest overview cards that show unavailable values instead of inventing zeroes.
- Admin mutation idempotency headers, durable operation receipt migration, and audit-write failure handling.
- High-risk admin mutations now require a signed AAL2/MFA claim in addition to the database membership role; read-only dashboard actions remain available for status and setup.
- Admin Settings now provides an authenticated Supabase TOTP enrollment and verification flow, with no factor secret persisted by the application.
- Admin Settings now exposes support-AI integration health plus an AAL2/idempotent safety-settings workflow: kill switch, bounded token/turn limits, and daily/monthly budgets are written through a service-only audited transaction; enablement is refused when provider/worker secrets are absent, and secret values never reach the browser.
- Support-AI settings now have database-owned revisions, recent history, and a bounded worker/admin circuit-breaker control; terminal provider failures pause new claims for five minutes and an AAL2 admin can clear the pause through an audited action.
- Manual premium access routed through the provider-separated entitlement reconciler.
- Manual access grants have their own expiry/revoke ledger; active Stripe, PayPal, and manual grants reconcile without erasing another valid source.
- Entitlement-owned AI limit column with Stripe, PayPal, and manual provider support.
- First-party analytics event table, allowlist, sensitive-field rejection, deduplication, account-created trigger, and verified Stripe/PayPal purchase events.
- Paid conversion calculation in the admin snapshot from durable account-created and provider-verified purchase events.
- Entitlement-aware admin reads with expiry handling and a read-only subscriptions ledger.
- Subscriptions now include source-backed Stripe and PayPal webhook receipt history with processed, skipped, failed, and in-flight states; unsupported provider actions remain explicitly disabled.
- Billing now has provider/environment-specific subscription and transaction projection tables, service-only upsert/record RPCs, Stripe invoice/subscription projection hooks, PayPal subscription/transaction projection hooks, and an admin reconciliation view that keeps missing migrations and unavailable rows explicit.
- Billing reconciliation now has a provider/environment lease table, serialized run claim/complete/fail RPCs, a bounded internal worker that re-fetches Stripe and PayPal state through ownership checks, paginates bounded PayPal transaction history, preserves sandbox/live projection labels, and exposes an admin health view that distinguishes failed observations from webhook receipts.
- Billing actions now have a disabled-by-default provider capability matrix, amount/currency limits, durable idempotent intent and attempt/receipt tables, an MFA-protected admin preview/intent boundary, and fail-closed unsupported responses; provider sandbox execution remains gated until the capability policy and worker credentials are reviewed.
- Billing action execution now has a secret-bound, leased worker boundary for reviewed Stripe/PayPal cancel, resume, refund, and customer-approval plan-change flows; provider uncertainty records `pending_reconciliation`, unsupported operations never become false successes, and the worker remains disabled by the capability matrix until sandbox review.
- AI & Jobs now has an operations panel with profile usage totals, allowance totals, and separate auto-apply job/run status counts; safe retry, cancel, and reconciliation-request controls are audited and idempotent, while unknown provider cost/latency and employer-facing submission remain unavailable.
- AI & Jobs status reporting now separates the actual `auto_apply_jobs` lifecycle states from `auto_apply_runs` execution states, with local browser coverage for both panels.
- Accessible admin action dialog replacing browser `prompt` / `confirm`, with Escape close and focus restoration.
- Support conversation core with customer/guest identity separation, durable messages, immutable events, read cursors, delivery outbox, idempotent operations, and service-only guest-token functions.
- Customer support widget and operator inbox wired to separate customer replies and internal notes, with searchable queue, assignment/CAS takeover, priority/tags triage, read acknowledgement, resolution/reopen, and handoff actions; the customer widget now reads the server-backed hours, queue-capacity, and live-presence context before submission and labels offline/open/queued states truthfully.
- Support edge function body/rate guards and hashed, memory-only guest session tokens in the browser client.
- Support attachment foundation now uses a private 10 MB JPEG/PNG/PDF bucket, signed uploads, ownership-bound finalization, quarantine state, service-only scan transitions, and five-minute authorized downloads; text chat remains usable while scanning is unavailable.
- Support follow-up email delivery now has an agent-message trigger, service-only leased outbox claim/complete/retry/dead-letter RPCs, and a bounded Brevo worker with server-only credentials and HTML escaping; guest conversations without a verified email remain in-app only.
- Resolved support conversations now accept one durable, identity-bound customer rating/comment from either an authenticated customer or an active guest session; the customer widget and operator inbox expose the resulting feedback without mixing it into the transcript.
- Feedback operations now expose bounded operator tags, aggregate category/tag themes, and an idempotent improvement backlog with sanitized summaries, source-feedback linkage, priority/status/impact, and active-operator ownership checks; raw transcript text is never copied automatically.
- Support knowledge now has private versioned articles, source references, draft creation, reviewed publish/rollback actions, a manager-only admin panel, and a service-only published reader for future AI retrieval; no AI provider is enabled by this slice.
- Support AI now has a disabled-by-default settings row, leased run/usage tables, audited AAL2-protected kill-switch/budget settings, revision history with rollback, a service-only guarded commit that rejects stale handoff/message state, and a timeout-bounded structured-output worker; no provider, scheduler, or production enablement is configured.
- Support attachment scanning now has a service-only `SKIP LOCKED` lease/claim contract and an internal fail-closed worker endpoint: it validates size/signature, calls an explicitly configured scanner, retries transient failures, and never marks an upload clean without a scanner verdict.
- Bounded customer-directory projection with profile-sync trigger, indexed server search, stable cursor ordering, role-checked access, and a paginated admin “Load more” path.
- Role-checked customer detail reads now show bounded account, usage, billing-source, support-count, and first-party activity metadata without exposing private resume/application content.
- Date-bounded first-party analytics endpoint and admin view with event counts, derived rates, freshness/source metadata, and unavailable-state handling.
- Admin Analytics now offers a date-bounded CSV export of the same aggregate metrics and rates, with server-side allowlisting and formula-injection protection; it contains no customer rows or private content.
- Stripe entitlement events retain provider subscription IDs; PayPal webhook deliveries use a durable retryable event inbox.
- Resume and application creation now enter first-party analytics through database triggers with idempotent event keys.
- Successful resume exports emit a privacy-safe Google Analytics `resume_exported` event; application creation and exports remain free of resume content and identifiers.
- Optional GA/Vercel analytics now fail closed until an explicit visitor choice, persist Accept/Decline state, support withdrawal from the Privacy page, clear analytics cookies on withdrawal, and keep first-party server-confirmed purchase events separate from visitor analytics.
- Guest support sessions survive same-tab reload through session storage and reset cleanly when the short-lived token expires.
- Local browser QA now covers the disposable guest/operator support journey through handoff, takeover, separated notes and replies, resolution, guest follow-up, and CSAT with strict local-origin binding.
- Privacy lifecycle foundation now provides role-checked, idempotent export/deletion requests, explicit legal/accounting/security/support holds, cancellation for pending requests, and a service-only deletion-claim RPC; no immediate Auth deletion or fake download is exposed.
- Privacy exports now have a private 50 MB JSON bucket, service-only leased claim/complete/retry/expiry RPCs, an allowlisted export worker that excludes credentials, Gmail tokens, internal notes, and raw provider webhook payloads, and five-minute admin-signed download URLs for ready exports. Deletion invalidates pending/ready export objects before account removal.
- Privacy deletion requests now require a separate owner approval boundary, snapshot active Stripe/PayPal entitlements into an audited provider-cancellation review boundary, and fail closed until evidence is recorded and billing reconciliation marks provider rows inactive. The separate service-only deletion worker removes private storage and customer-owned data, unlinks retained accounting/audit aggregates, deletes Auth only after the data step succeeds, and completes only after Auth confirmation; neither the admin API nor review action calls a payment provider.
- Ban/delete/admin-revoke paths preserve the last active owner and record failed mutations through the existing idempotency receipt.
- Owner-only team administration now supports audited role changes for active members, with database-serialized role/revoke transactions, server-side role validation, self-change protection, and last-owner safeguards. Email-only access is represented as a seven-day, server-enforced invitation that can be reclaimed after expiry by a new owner action; email delivery and broader team settings remain separate work.
- Support Settings now includes a versioned, service-only hours/routing contract with validated timezone, business days, queue guard, first-response target, automatic-routing flag, revision history, audited owner/admin updates, operator presence TTLs, business-hour response deadlines, and truthful queue SLA status; it does not claim provider delivery.
- Admin invitations now have a service-only, expiring email outbox with trigger-based enqueueing, bounded leases, retry/dead-letter states, Brevo idempotency, and visible queued/sent/failed delivery state; delivery stays disabled until the provider secret and application URL are configured.
- Admin user-directory role compatibility now uses the verified JWT role accessor and is covered by both service-role and authenticated-owner local RPC replay checks.
- Authenticated local browser QA now covers the disposable owner flow, source-backed overview data, HTTP 200 admin API responses, Light-first default, persisted Dark mode, mobile drawer/Escape behavior, and overflow safety; screenshots are retained in `evidence/`.
